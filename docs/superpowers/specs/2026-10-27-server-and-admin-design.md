# 서버 붙이기 + 웹 어드민 설계

작성일: 2026-10-27 · 상태: 사용자 확인 대기 (검토자 질문 반영)

## 1. 왜 만드는가

wuzu(모바일 초대장 앱)를 실제 서비스로 열기 위해서다. 지금 앱은 회원·초대장·레터·결제·참석 응답·알림·공지가 모두 기기 안의 mock 으로 돌아간다(`src/services/mock`). 운영진이 회원·돈·콘텐츠를 보고 고칠 수 있어야 서비스를 열 수 있고, 그러려면 진짜 서버(DB)가 먼저 있어야 한다.

그래서 이 일은 두 덩어리다.

1. **서버 붙이기** — 앱의 mock 서비스를 진짜 DB·로그인·파일 저장으로 바꾼다. 앱 화면은 `src/services/types.ts` 인터페이스 뒤에 있으므로 구현만 갈아 끼운다.
2. **웹 어드민** — 같은 DB 를 운영진이 보고 고치는 웹 화면.

성공: 운영진 5명이 어드민 하나로 회원 문의·환불·신고·공지를 처리하고, 매일 아침 대시보드로 서비스 상태를 본다. 그리고 **파일 저장·전송 비용이 최소로 유지된다**(사용자가 특히 강조한 조건).

## 2. 목표 · 비목표 · 하면 안 되는 것

**목표** — 아래 9개 관리 기능 전부 (사용자 결정: "1~9번 다 간다").

1. 회원 관리
2. 레터·결제 관리 (결제 경로 구분)
3. 초대장 관리 (신고 처리 포함)
4. 방명록 관리
5. 공지사항 관리
6. 홈 배너 관리
7. 레터 상품·가격 설정
8. 대시보드 (차트 포함)
9. 템플릿 노출 관리 · 푸시 알림 보내기 · 약관 버전 관리

여기에 **저장소(용량) 화면**과 **작업 기록**을 더한다(아래 근거).

**비목표 (이번에 안 함)**
- 메뉴·기능별 권한 나누기 — 사용자: "다음 레벨". 지금은 운영자 전원 같은 권한.
- PG 결제 연동·웹 충전 페이지 — 사용자: "인앱부터 붙이고… 이건 그냥 염두에". DB·어드민은 `pg` 경로를 받을 수 있게만 만든다. **인앱결제(애플·구글) 연동은 이번 범위**(2단계).
- 휴대폰 동영상 압축(Expo Go 에서 불가, 정식 빌드 이후).

**하면 안 되는 것**
- 저장·전송 비용이 관리 안 되는 구조 (원본 그대로 저장, 안 쓰는 파일 방치, 트래픽 과금이 큰 저장소).
- 누가 돈·회원 데이터를 건드렸는지 알 수 없는 것.
- 하객 화면(공개 링크)이 서버 붙인 뒤 느려지거나, 로그인 없이 남의 초대장 데이터를 고칠 수 있게 되는 것.

## 3. 만드는 방식 (결정 사항)

| 항목 | 결정 | 누가 |
|---|---|---|
| DB·로그인·서버 함수 | Supabase (Postgres, Auth, Edge Functions) | 제안 → 사용자 승인 |
| 사진·영상 파일 | Cloudflare R2 (전송 요금 0원) | 제안 → 사용자 승인 |
| 어드민 | Next.js 웹, Vercel 배포 | 제안 → 사용자 승인 (픽처히어와 같은 방식) |
| 어드민 모양 | 픽처히어 어드민과 같은 틀: 왼쪽 220px 사이드바 메뉴(선택 메뉴는 브랜드 색 배경·흰 글자), 오른쪽 표 위주 본문, 맨 아래 로그아웃. 색·로고만 wuzu 것(브랜드 `#183A2E`) | 사용자 |
| 운영자 | 대표 포함 약 5명, 전원 같은 권한 | 사용자 |
| 만료 초대장 파일 | 만료 후 30일 보관, 그동안 연장 없으면 파일 삭제 | 제안 → 사용자 "ㅇㅋ" |
| 하객 링크 | 하객이 앱 없이 여는 **웹 주소**. 도메인은 새로 산다(이름 미정, 사용자가 구매). 초대장 주소는 **추측할 수 없는 난수 조각**(예: `/i/k3Fq9xT2mA`, 10자 이상)으로 자동 생성 — 순번·초대장No 를 주소에 쓰지 않는다 | 사용자 |
| 하객 링크 서비스 방식 | 앱의 하객 화면(`src/app/invite/[id].tsx`)을 Expo 웹으로 배포(Vercel). 카카오톡·문자 미리보기(제목·표지 썸네일 OG 태그)는 링크 주소에서 서버가 만들어 준다. 링크를 연 기기에 앱이 있으면 앱으로 연다(유니버설 링크·앱 링크) | Claude 제안, 사용자 "1번" 답에 이의 없음 |
| 가입 지급 레터 | 50레터(첫 초대장 활성화 1회분). 원장 종류 `signup_bonus`, 매출 합계에서 뺀다. 같은 사람(같은 소셜 계정·이메일·휴대폰)이 탈퇴 후 다시 가입하면 지급 안 함 | 사용자 "50레터만" |
| 로그인 | 이메일 + 카카오 + **애플**(앱스토어 심사 4.8: 다른 회사 로그인이 있으면 필요). 구글은 안드로이드 출시 때 | Claude 판단 |
| 탈퇴 확정 회원 | 개인정보(이름·이메일·휴대폰·생년월일)·파일·초대장·방명록은 지우거나 익명화. 결제·레터 원장은 전자상거래법(대금결제 기록 5년)에 따라 회원 식별만 지운 채 5년 보관. 작업 기록은 대상 ID 만 남긴다 | Claude 판단 |
| 파일 정리된 초대장 | 나의 초대장에 "보관 기간 끝남"으로 남고 연장·재활성화 불가(새로 만들어야 함). 하객 링크는 "기간이 끝난 초대장이에요" 안내 화면 | Claude 판단 |

**구현자 재량 (Claude 판단, 사용자 확인 전)**
- 저장소 위치: 어드민은 이 저장소 안 `admin/` 폴더(별도 Next.js 앱), DB 스키마·마이그레이션은 `supabase/` 폴더. 앱·어드민이 같은 스키마를 보므로 한곳에 둔다.
- 운영자 계정: 어드민 안에서 기존 운영자가 이메일로 초대해 만든다. 공개 가입 화면 없음. `admins` 표에 `role` 칸을 두되 지금 값은 모두 `admin` (나중 권한 나누기 대비).
- 어드민 로그인은 Supabase Auth 를 쓰고, 어드민 전용 DB 접근은 서버(서비스 키)에서만 한다. 브라우저에 서비스 키를 내리지 않는다.

## 5. 파일 저장 비용 (사용자 핵심 조건)

사용자: "최대한 압축해서 많은 과금이 안 나오게끔 관리".

현재: 사진은 긴 변 1280px·JPEG 70%(`features/invitation/media.ts`, `features/canvas/media.ts`). 캔버스 GIF 는 장당 10MB·3장, 동영상은 15초·30MB·1개 제한(`CANVAS_LIMITS`).

1. **사진은 WebP** 로 저장: 본 이미지 긴 변 1080px, 썸네일 긴 변 400px 두 벌. 장당 대략 100~200KB 목표. 기기에서 변환해 올린다(서버 이미지 변환 요금을 쓰지 않는다).
2. **GIF·동영상 상한 낮추기** (Claude 판단): GIF 장당 5MB, 동영상 15초·20MB. 넘으면 올리기 전에 안내. 동영상 압축은 정식 빌드 이후 과제.
3. **R2 에 저장**하고 하객에게는 R2 공개 주소(+Cloudflare 캐시)로 보낸다. 청첩장은 하객 수백 명이 같은 사진을 받으므로 저장보다 전송량이 비용의 대부분 — 전송 요금 0원인 R2 를 쓰는 이유.
4. **업로드는 서버가 발급한 서명 주소로 기기→R2 직접**. 서버를 거치지 않는다. 서명 발급 때 파일 종류·크기 상한을 확인한다.
5. **정리 작업 (매일 1회 서버 예약 작업)**
   - 초안·초대장에서 더는 안 쓰는 파일(사진 교체 등) → 24시간 뒤 삭제
   - 한 번도 활성화하지 않고 90일 동안 수정 없는 초안 → 파일 삭제 (Claude 판단, 앱에 미리 안내 문구 필요)
   - 만료 후 30일 지나도 연장 없는 초대장 → 파일 삭제, 초대장은 "파일 정리됨" 표시
   - 탈퇴 확정 회원 → 파일 삭제
6. **어드민 '저장소' 화면**: 전체 용량, 이번 달 증가량, 종류별(사진·GIF·영상) 비중, 용량 큰 초대장 순위, 정리 작업 실행 기록·지운 용량.

## 6. 어드민 화면

왼쪽 메뉴 순서: 대시보드 · 회원 · 초대장 · 방명록·신고 · 레터·결제 · 공지 · 배너 · 상품·가격 · 템플릿 · 푸시 · 약관 · 저장소 · 운영자·작업 기록.

모든 목록은 검색·걸러 보기·페이지 나눔·CSV 내려받기. 돈·회원 상태·콘텐츠를 바꾸는 버튼은 확인 창을 거치고 작업 기록에 남는다.

### 6.1 대시보드 (사용자: "차트도 활용해서 다채롭게, 내용 넣어 주면 손봐 줄게")
- 숫자 카드: 오늘 신규 초대장 · 오늘 신규 결제(건·금액) · 오늘 가입 · 이번 주 만료 예정. 각각 어제·지난주 대비 증감.
- 차트: 초대장 생성 추이 30일(테마별 색), 매출 추이 30일(결제 경로별), 테마별 비중, 만들기→활성화 비율.
- 순위: 링크 공유 횟수 TOP 10, 하객 조회 TOP 10.
- 할 일: 이번 주 만료 예정 목록(만료일순), 처리 안 된 신고, 확인 필요한 스토어 환불.

### 6.2 회원
목록(가입일·경로·상태·레터 잔액·초대장 수), 상세(정보·초대장·레터 내역·결제), 정지/해제, 탈퇴 신청 처리 현황, 레터 수동 지급·회수(사유 필수).

### 6.3 레터·결제
- 결제 목록: **결제 경로(애플 인앱 / 구글 인앱 / PG) 구분 표시와 걸러 보기**, 경로별 합계. 운영자 수동 지급은 레터 내역에 함께 보이되 결제 합계에는 넣지 않는다.
- 환불:
  - **애플·구글 인앱 (먼저 붙는 경로)**: 환불 여부는 스토어 정책·심사로 정해지고 우리가 결정하지 않는다. 스토어 환불 알림(애플 App Store Server Notifications, 구글 Real-time developer notifications)을 서버가 받아 "스토어 환불됨"으로 바꾸고 그 결제의 레터를 자동 회수. 이미 써서 잔액이 모자라면 남은 만큼만 회수하고(잔액은 0 아래로 내려가지 않는다) "확인 필요"로 남겨 운영자가 판단.
  - **PG (나중)**: 우리 환불 규칙을 쓴다(사용자 결정). 결제 후 7일 안이고 그 결제의 레터를 하나도 안 썼으면 전액 환불. 그 밖에는 **남은 레터 수만큼만** 부분 환불(1레터 = 결제 단가 기준). 잔액은 0 아래로 내려가지 않는다. 어드민 [환불] → 환불액 계산 표시 → PG 취소 → 레터 회수 → 기록.
  - 레터를 쓰는 순서: 무료 지급(가입·운영자·이벤트) 레터 먼저, 그다음 충전한 레터 중 오래된 것부터 (사용자 기존 약관). 무료 지급분은 환불 대상이 아니다.
- 레터 사용 내역(활성화·연장·수정) 조회.

### 6.4 초대장
목록(테마·상태·활성화·만료일·공유·조회 수·용량), 하객 화면 미리보기, 숨김(기존 `banned` 칸)/해제, 만료일 조정(CS 보상, 기록 남김).

### 6.5 방명록·신고
- 방명록 전체 최신순, 금칙어 걸린 글 표시, 숨김/삭제.
- 신고 목록 → 초대장 보기 → 숨김 또는 기각. **앱 하객 화면에 [신고하기] 버튼을 새로 넣는다**(지금 없음).

### 6.6 공지 · 배너 · 상품·가격 · 템플릿 · 약관
- 공지: 작성·수정·게시/내림, 앱 알림(`AppNotification` category notice)으로도 보낼지 선택.
- 배너: 지금 앱 배너 모양(제목·본문·배경색·글자색·그림) 그대로 + 링크·순서·노출 기간.
- 상품·가격: 레터 충전 상품, 활성화 비용·기간, 연장 옵션, 수정 비용. 바꾸면 앱이 다음 실행부터 서버 값을 쓴다. 스토어 상품 금액은 스토어 콘솔에서도 맞춰야 한다는 안내를 화면에 둔다.
- 템플릿: 테마별 템플릿 켜기/끄기·순서.
- 약관: 버전 추가·시행일, 앱은 시행일이 지난 최신 버전을 보여 준다.

## 7. 앱 쪽에서 바꿀 것

- `src/services` 에 Supabase 구현을 더하고 mock 과 바꿔 끼운다. 테스트는 mock 그대로 쓴다.
- 로그인: 이메일 + 카카오(지금 화면 그대로) → Supabase Auth.
- 파일: 올리기 전 WebP 변환·썸네일, 서명 주소로 R2 직접 업로드, 상한 낮추기.
- 공지·배너·상품·가격·약관·템플릿 노출을 서버에서 읽기 (앱 안 상수는 서버 못 읽을 때 대비 기본값으로 남긴다).
- 하객 화면: 조회 기록, 공유 버튼에서 공유 기록, [신고하기] 버튼.
- 하객 화면(공개 링크)은 로그인 없이 읽기만 된다. 쓰기는 방명록·참석 응답·신고만, 서버 함수로 검사.

## 8. 단계

한 번에 하지 않는다. 각 단계는 따로 계획을 쓰고 끝마다 화면 확인(QA)과 HTML 보고서.

1. **기반**: Supabase 프로젝트·스키마, 어드민 뼈대(로그인·사이드바·운영자·작업 기록), 앱 로그인(이메일·카카오·애플)·회원·초대장·방명록·참석 응답을 서버로. R2 업로드와 WebP 변환. **하객 웹 링크**(난수 주소, Expo 웹 배포, 미리보기 태그). 어드민 회원·초대장 조회. 도메인이 아직 없으면 Vercel 기본 주소로 먼저 띄우고 도메인 구매 후 바꾼다.
2. **돈**: payments·레터 원장 서버화, **애플·구글 인앱결제 연동(정식 빌드 필요, 서버 영수증 검증)**, 결제 경로 구분, 스토어 환불 알림 처리, 레터 지급·회수, 가입 지급 50레터. 어드민 레터·결제 화면. PG 는 경로·환불 계산 규칙만.
3. **콘텐츠 운영**: 방명록·신고(앱 신고 버튼), 공지·배너·상품·가격·템플릿·약관을 서버에서. 공유·조회 기록. 대시보드 차트.
4. **나머지**: 푸시, 저장소 화면, 정리 예약 작업.
