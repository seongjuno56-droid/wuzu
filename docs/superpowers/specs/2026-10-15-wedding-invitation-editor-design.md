# 결혼식 초대장 제작 기능 설계 (2단계)

화면 설계 이미지 21장(홈 상태별 카드, 미리보기, 온보딩 모달, Step1~5, 섹션별 바텀시트, 방명록)을 기준으로 한다.
서버 없음 — 모든 저장은 mock 서비스(AsyncStorage). 실제 서버 도입 시 서비스 구현만 교체한다.

## 1. 홈 / 탭 / 온보딩
- 초대장 현황 카드 3상태
  - 비회원: "WUZU에 온 것을 환영해요!" + 로그인
  - 회원·초대장 있음: "{닉네임}님의 초대장 현황", 현재 활성화 중인 초대장 N장, 최근 제작(최근 저장 이름, 말줄임) — 카드 전체 탭 → 나의 초대장
  - 회원·0장: "{닉네임}님만의 초대장이 정말 기대되네요!", 0장, [나만의 초대장 제작하기] → 제작
- "WUZU가 추천하는 초대장": 추천 카드(썸네일=템플릿 표지, 이름, 해시태그) → 템플릿 미리보기
- 배너: 4초 자동, 스와이프/탭, 인디케이터
- 공지사항: 비회원 → 로그인, 회원 → 준비 중 안내(마이페이지 > 우쥬 정보 > 공지사항은 다음 단계)
- 탭 '나의 초대장': 비회원 → 로그인
- 카카오 첫 로그인: 약관/정보 단계 없이 가입 → 홈에서 [mp] 회원정보 기입(생년월일·성별·마케팅)
  - 다음에 하기: 생년월일·성별 '-', 마케팅 미동의 / 확인: 선택값 저장 (유효성 검사 없음)

## 2. 제작 흐름
- Step1 테마 선택(기존) → Step2 템플릿 선택(기존 캐러셀) — 미리보기는 전체화면 모달, 선택하기 → Step3 (비회원은 로그인)
- Step3 입력항목 선택: 기본정보·예식정보·인사말(고정 사용), 토글: 계좌번호·갤러리·방명록·엔딩·BGM → Step4
- Step4 페이지 순서: 표지·인사말(고정 상단), 갤러리·예식정보·방명록·계좌번호(드래그), 엔딩(고정 하단). 미사용 항목은 숨김. 이전 → Step3, 정보 입력 → Step5
- Step5 정보 입력
  - 헤더: ← (초대장 설정 = Step3, 입력값 유지), 임시저장, 최종저장
  - 상단: 실시간 미리보기 / 하단: 섹션 탭바(작성 상태 점: 미완료 빨강, 완료 초록)
  - 탭 선택 → 바텀시트(▼ 닫기, 제목, ✓ 확인 — 유효할 때만 활성, 확인 시 완료 표시)
  - 임시저장: 이름(2~30자) 모달 → 저장 완료 모달 [메인으로][나의 초대장으로 이동]
  - 최종저장: 모든 사용 섹션이 완료일 때만 이름 모달 → 저장 완료(활성화)
  - 작성 중 이탈: "페이지를 이동하시겠습니까? 입력한 정보는 저장되지 않습니다." [닫기][이동] (웹 beforeunload 포함)

## 3. 섹션 입력 규칙
| 섹션 | 규칙 |
|---|---|
| 기본정보 | 신랑·신부: 이름+호칭 필수(각 10자, 기본 호칭 아들/딸). 부모: 선택, 이름↔호칭 짝 필수, 故人 체크 |
| 예식정보 | 예식장명* 1~20 / 주소*: 주소 검색(다음 우편번호) 또는 직접 입력(우편번호·주소·상세 각 100) / 층·홀 50(줄바꿈) / 예식일* 기본 오늘+7 / 예식시간* / 지도: 사용(주소검색=지도 카드, 직접입력=이미지 1~3장)·사용안함 / 옵션: 캘린더, 디데이 |
| 인사말 | 내용* 1~300(줄바꿈) / 사진 선택 1장(jpg·jpeg·png) / 신랑·신부 이름 삽입 기본 true("길동, 춘향 드림.") |
| 계좌번호 | 안내문 선택(기본 문구, 300) / 신랑*·신부*: 은행 1~10 + 계좌 1~20 / 부모: 선택, 은행↔계좌 짝 필수 |
| 갤러리 | 스와이프/그리드, 그리드: 2단/3단·더보기(4번째 줄부터 접힘) / 사진* 최소 4~최대 12, 드래그 정렬 |
| 방명록 | 스타일1/스타일2 |
| 엔딩 | 스타일1/2 / 내용* 기본 문구, 300 / 사진 선택 최대 3, 드래그 정렬 |
| BGM | 업로드 MP3·M4A·AAC·WAV·OGG, 5MB 이하 / 재생·일시정지·정지·삭제 / Mute 버튼 색상 블랙·화이트 |

허용되지 않은 확장자: "허용되지 않은 확장자입니다." 토스트.

## 4. 초대장 보기 (미리보기·저장본 공통 렌더러)
표지 / 인사말(+사진, 이름 삽입) / 갤러리 / 예식정보(날짜·요일·시간, 캘린더 강조, D-Day 실시간 카운트다운·"결혼식까지 N일 남았습니다.", 장소·층홀·주소, 지도 카드) /
마음 전하실 곳(안내문, 신랑측·신부측 계좌 복사하기) / 방명록(최근 2개, 작성하기 | 전체보기) / 엔딩 / BGM 음소거 버튼.

방명록: 작성(이름* 10, 비밀번호* 4~20, 내용* 300 → "방명록이 등록되었습니다." → 전체보기),
전체보기(X → 비밀번호 확인 모달, 틀리면 "비밀번호가 일치하지 않습니다.", 성공 "삭제가 완료되었습니다." / 초대장 작성자는 비밀번호 없이 확인 모달 후 삭제).

## 5. 설계 충돌 결정
- 방명록 글자 수: 작성 화면(50/500)과 설정 설명(10/300)이 다름 → 이름 10, 비밀번호 4~20, 내용 300 적용
- 갤러리 장수: 화면(12)과 설명(30)이 다름 → 4~12 적용
- 지도: 실제 지도 SDK는 API 키 필요 → 주소 카드 + 카카오맵/네이버지도 링크로 대체(키 확보 시 교체)
- 사진·BGM: 서버 없음 → 기기 내 저장(웹은 사진 축소 저장, BGM은 새로고침 시 유실)

## 6. 저장 구조
`invitationService`: list(ownerId) / get(id) / save(invitation) / remove(id), 방명록 list/add/remove(비밀번호 또는 작성자).
초대장 상태: draft(임시저장) / active(최종저장 = 활성화).
