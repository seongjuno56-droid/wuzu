# 나의 초대장 · 레터(화폐) · 인앱 충전 설계

설계 화면 13장(나의 초대장 목록·필터, 상태별 카드, 초대장 활성화, 기간 연장 구매, 더보기, 방명록 관리, 이력 열람, 초대장 수정)을 기준으로 한다.
서버 없음 — 모든 저장·결제는 mock 서비스. 실제 서버·인앱 결제 도입 시 서비스 구현만 교체한다.
이 작업이 끝난 뒤 `2026-10-16-canvas-cover-and-view-modes-design.md`(표지 캔버스)를 이어서 진행한다.

## 0. 결정 사항
- 순서: 나의 초대장·레터 먼저(상태·구매 체계가 저장 흐름의 바탕), 캔버스는 그 위에.
- 화폐 이름은 **레터**. 설계 화면의 "총 젤리 N개 차감"은 "총 N레터 차감"으로 쓴다.
- 충전은 **인앱 결제**(iOS App Store / Google Play). PG는 이후 웹 충전·국내 대체 결제로 붙인다.
- 디자인은 기존 화해 스타일 유지(다크 블록 버튼, 파란 틴트). 설계 화면의 분홍 강조색은 쓰지 않는다.
- 초대장 이름 규칙: **1~30자**로 통일(저장 모달·이름 수정 모두).
- 구매 전 생체인증: 앱에서 가능하면 지문·얼굴 확인, 안 되면 확인 모달만.

## 1. 상태 체계
저장 상태는 두 가지(`draft` 임시저장 / `final` 최종저장)만 두고, 화면 상태는 계산한다.

| 화면 상태 | 조건 (위에서부터 먼저 맞는 것) | 배지 |
|---|---|---|
| 사용불가 | `banned` | 어두운 회색 |
| 작성중 | `status === 'draft'` | 주황 |
| 비활성화 | `final`, 활성화한 적 없음(`expiresAt` 없음) | 빨강 |
| 활성화 | `final`, `now < expiresAt` | 초록 |
| 기한만료 | `final`, `now >= expiresAt` | 남색 |

- 초대장 필드 추가: `number`(초대장No, 11자리 숫자 문자열), `activatedAt?`, `expiresAt?`(ISO), `banned?: boolean`, `guestbookSeenAt?`(ISO).
- 기존 `status: 'active'` 저장본은 `final`(비활성화)로 보정한다. `number`가 없으면 만들어 넣는다.
- 최종저장 = 비활성화. 활성화는 구매로만 된다.
- 홈 현황 카드의 "현재 활성화 중인 초대장"은 화면 상태 '활성화' 개수.
- 하객 보기(`/invite/[id]`): 활성화 상태가 아니면 "지금은 볼 수 없는 초대장이에요." 안내(작성자 본인은 미리보기로 볼 수 있음). 공유는 활성화일 때만.

## 2. 레터 · 가격 · 기간
### 2-1. 가격 (설정 파일 한 곳: `src/features/wallet/pricing.ts`)
| 상품 | 레터 | 비고 |
|---|---|---|
| 서비스 활성화 | 50 | 공유 기능 활성화, 기본 15일 |
| 기간 연장 +30일 | 30 | |
| 기간 연장 +60일 | 55 | 정가 60 취소선 |
| 기간 연장 +180일 | 150 | 정가 180 취소선 |
| 활성화된 초대장 수정 | 5 | 수정할 때마다 |

### 2-2. 기간 계산
- 활성화(비활성화·기한만료에서): `activatedAt = now`, `expiresAt = now + 15일 + 연장일`.
- 연장(활성화 중): `expiresAt += 연장일`(`activatedAt` 유지).
- 표시: `YYYY.MM.DD ~ YYYY.MM.DD 까지 활성화`(시작일 ~ 종료일).
- 사용불가 초대장은 활성화·연장 불가(서비스가 거부).

### 2-3. 결제 처리 (wallet 서비스)
- `spend`는 한 번에 처리: 잔액 확인 → 레터 차감 → 초대장 기간/수정 반영 → 기록 추가. 부족하면 아무것도 바꾸지 않고 `insufficient` 반환.
- 기록(이력) 항목: 이력No(11자리), 시각, 종류(`activate`·`extend`·`edit`·`charge`), 제목(초대장 활성화 / 기간 연장 구매 / 초대장 수정 / 레터 충전), 내용 줄(서비스 활성화 −50레터, 이용 기간 연장 +30일 −30레터, 초대장 컨텐츠 수정 −5레터, 레터 충전 +110레터), 초대장 id(충전은 없음).
- mock 새 계정 시작 잔액 200레터(설계 화면 값).

## 3. 충전 (인앱 결제)
- 레터 상품(설정 파일): 50레터 ₩5,500 / 110레터(100+보너스 10) ₩11,000 / 330레터(300+30) ₩33,000 / 550레터(500+50) ₩55,000. 앱스토어 가격 등급 기준, 확정 전 기본안. **[변경 메모]** 충전 상품은 마이페이지 설계(`docs/superpowers/specs/2026-10-20-mypage-design.md` 0장)의 10/50/100/300/500 레터로 바뀐다. 위 110/330/550 표기는 그 메모로 대체한다.
- `paymentService` 인터페이스: `products()`, `purchase(productId) → 'success' | 'cancelled' | 'failed'`. 성공 시 wallet에 충전 기록.
- 지금은 mock: 플랫폼에 맞춰 **iOS형(App Store 시트)** 또는 **구글형(Google Play 시트)** 결제 시트를 띄운다(웹은 iOS형). 시트에서 [구매]/[취소]를 고르고, 개발 중 실패 상황 확인용 [결제 실패 시험] 링크를 둔다.
- 실제 도입: `expo-iap`(개발용 빌드 필요, Expo Go 불가) + App Store Connect·Play Console 소모성 상품 등록 + 서버 영수증 검증 후 레터 지급.
- 레터 지갑 화면(`/wallet`, 헤더 레터 배지에서 진입): 보유 레터, 충전 상품 목록, [충전 내역][사용 내역] 탭.
  **[변경 메모]** 레터 지갑 화면은 마이페이지 설계(`2026-10-20-mypage-design.md`)의 My 레터(`/wallet`)가 대신한다.
- 레터 부족 모달 [레터 충전] → 지갑 화면 → 충전 후 뒤로 가면 원래 구매 화면이 그대로 있다(선택값 유지, 잔액 새로고침).

## 4. 화면
### 4-1. 나의 초대장 (`(tabs)/my-invites`)
- 헤더: "나의 초대장" + 오른쪽 레터 배지(`레터 200`).
- 필터 2개(누르면 바텀시트, 선택 후 [선택]):
  - 제작 연도: 전체 + 내 초대장의 제작 연도(중복 없이 최신순).
  - 상태: 전체 / 작성중 / 비활성화 / 활성화 / 기한만료 / 사용불가.
- 정렬: 제작일시 최신순.
- 카드: 제작일시 `YYYY.MM.DD HH:mm:ss`, `초대장No. …`, 상태 배지, `#결혼식 초대장`, 이름, 상태 문구, 오른쪽 썸네일(표지 축소, 누르면 미리보기 / 사용불가는 "미리보기 불가").
  | 상태 | 문구 | 버튼 |
  |---|---|---|
  | 작성중 | 작성 완료 후 초대장 활성화 가능 | [초대장 완성하러 가기] → 편집 / ⋮ |
  | 비활성화 | 활성화 전까지 무제한 수정 가능 | [초대장 활성화 (레터 50)] [방명록] / ⋮ |
  | 활성화 | 시작 ~ 종료 까지 활성화 (초록) | [기간 연장] [공유하기] [방명록·(New) 방명록] / ⋮ |
  | 기한만료 | 활성화 전까지 무제한 수정 가능 | [초대장 활성화 (레터 50)] [방명록] / ⋮ |
  | 사용불가 | 관리자로부터 제재받은 초대장 | [관리자로부터 제재된 초대장](비활성) [🗑 삭제] |
  - [방명록]: 방명록을 끈 초대장은 비활성(회색). "(New)"는 마지막 확인 이후 새 글이 있을 때.
- 빈 화면: "제작된 초대장이 없습니다." + [초대장 제작하러 가기]. 필터 결과만 비면 "조건에 맞는 초대장이 없습니다."
- 비로그인: 로그인 화면으로(기존과 같음).

### 4-2. ⋮ 더보기 (바텀시트: 초대장No, "- 결혼식 초대장 -", 이름)
- [이력 열람] → `/invitation/[id]/history`
- [초대장 이름 수정] → 모달(현재 이름 채움, 1~30자, 글자 수 `(n/30)`, 1자 이상일 때 [수정하기] 활성) → "수정이 완료되었습니다." 토스트
- [초대장 수정] → 편집기 수정 모드(4-6)
- [삭제] → "삭제하시겠습니까? 삭제 시 복구할 수 없습니다." [취소][삭제하기] → "삭제가 완료되었습니다."
- 사용불가 초대장의 더보기는 [이력 열람][삭제]만.

### 4-3. 초대장 활성화 (`/invitation/[id]/activate`, 전체 화면 모달)
- 헤더 "초대장 활성화" + ✕.
- 꼭 확인해 주세요!: 활성화한 시점부터 사용 기간이 카운트 / 활성화 전까지 무제한 수정 / 활성화 이후 수정은 수정권(레터 5) 필요 / 사용불가 초대장은 활성화·연장 불가.
- 초대장 정보(제작일시·No·#결혼식 초대장·이름) → 보유 레터 → 이용권 구매(서비스 활성화 50레터, 공유하기 기능 활성화(기본 15일 제공)) → 이용 기간 연장(선택 안함 / +30 / +60 / +180, 기본 선택 안함) → 구매 정보(보유중인 레터, 서비스 이용료 차감, 이용기간 연장 +N일 차감, "총 N레터 차감", "구매 후 남은 레터 N" — 음수면 그대로 보여줌) → [레터로 구매하기] → 하단 약관 링크(이용약관 | 유료 이용약관 | 개인정보 처리방침 | 구매 복원).
- [레터로 구매하기]:
  - 남은 레터 < 0: "레터가 부족합니다. 레터를 충전하시겠습니까?" [취소][레터 충전].
  - 아니면 "상품을 구매하시겠습니까? 구매 시 서비스가 활성화 됩니다." [취소][구매하기] → 생체인증(가능할 때) → 처리 → "구매를 완료하였습니다." 토스트 → 화면 닫힘 → 목록 새로고침.
  - 생체인증 취소·실패: 아무것도 하지 않음("인증이 취소되었어요.").
- [구매 복원]: 인앱 결제 연동 후 동작. 지금은 "복원할 구매 내역이 없어요." 안내.
- 약관 링크: 기존 약관 화면이 있으면 연결, 없으면 준비 중 안내.

### 4-4. 기간 연장 구매 (`/invitation/[id]/extend`)
- 헤더 "기간 연장 구매". 4-3과 같은 구조에서 이용권 구매 칸이 없고, 초대장 정보에 현재 활성화 기간(초록)을 보인다. 기본 선택 안함 → 총 0레터, 이 때 [레터로 구매하기] 비활성.
- 확인 모달: "상품을 구매하시겠습니까?" [취소][구매하기].

### 4-5. 방명록 관리 (`/invitation/[id]/guestbook`)
- 방명록을 켠 초대장에서만 진입. 헤더 "방명록" + ✕.
- 카드: 이름, 작성일시 `YYYY.MM.DD HH:mm:ss`, 내용, 오른쪽 [✕] 삭제, 왼쪽 위 "신규" 띠(마지막 확인 이후 글).
- [✕] → "삭제하시겠습니까?" [취소][삭제하기] → 작성자 권한으로 삭제.
- 처음 50개, 남은 게 있으면 "[50개 더보기 ▾]"(남은 수가 50 미만이면 버튼에 그 수로 보인다. 예: "12개 더보기 ▾"). 비면 "작성된 방명록이 없습니다."
- 화면을 나갈 때 `guestbookSeenAt = now` 저장(다음부터 "신규"·"(New)" 사라짐).

### 4-6. 초대장 수정 (편집기 수정 모드)
- 기존 Step5 편집기를 수정 모드로 연다. 헤더 "초대장 수정" + [설정](Step3 입력항목 선택으로) [임시저장] [수정].
- 작성중·비활성화·기한만료: [수정] = 기존 최종저장(이름 모달 → 저장 완료). 무료. (작성중에서는 지금처럼 [최종저장] 문구)
- 활성화:
  - [임시저장] 숨김(하객이 보는 초대장에 반쯤 고친 내용이 섞이지 않게).
  - [수정] → 입력 누락이면 "초대장 정보를 모두 입력하세요." [확인] (+ 빨간 점 탭으로 이동).
  - 아니면 "수정 (레터 -5)" 모달(초대장No, "- 결혼식 초대장 -", 이름, 보유 레터, [수정 (레터 -5)][이전]) → 생체인증 → 차감·저장 → "수정이 완료되었습니다. (레터 -5개 차감)" → 나의 초대장으로.
  - 레터 부족: "레터가 부족합니다. 레터를 충전하시겠습니까?" [취소][레터 충전].
- 이탈 경고는 기존과 같다.

### 4-7. 이력 열람 (`/invitation/[id]/history`)
- 헤더 "이력 열람" + ←. 초대장 정보(활성화 기간 초록 / "초대장 비활성화" 빨강).
- 기록 카드(최신순): 이력No, 일시 `YYYY-MM-DD HH:mm:ss`, 제목, 내용 줄과 차감 레터. 없으면 "이력 정보가 없습니다."

### 4-8. 공유하기
- 앱: 기기 공유 시트(`Share.share`)에 초대장 주소. 웹: 주소 복사 + "주소를 복사했어요." 토스트.
- 주소는 지금 앱의 웹 주소 `/invite/[id]`(실제 공유 도메인은 서버 단계).

### 4-9. 레터 지갑 (`/wallet`)
- 보유 레터, 충전 상품 4개(레터 수 + 가격 + 보너스 표시), [충전 내역][사용 내역] 탭(기록 카드 형식은 4-7과 같음, 사용 내역은 초대장 이름 포함).

## 5. 서비스 인터페이스
```ts
interface WalletService {
  balance(userId: string): Promise<number>;
  history(userId: string, filter?: { invitationId?: string; kind?: 'charge' | 'spend' }): Promise<LedgerEntry[]>;
  /** 활성화(+연장) / 연장 / 수정 — 한 번에 처리 */
  spend(userId: string, order: SpendOrder): Promise<{ ok: true; invitation: Invitation; balance: number } | { ok: false; reason: 'insufficient' | 'blocked' | 'not_found' | 'invalid' }>;
  charge(userId: string, productId: string): Promise<number>; // 결제 성공 후에만 호출
}
type SpendOrder =
  | { kind: 'activate'; invitationId: string; extendDays: 0 | 30 | 60 | 180 }
  | { kind: 'extend'; invitationId: string; extendDays: 30 | 60 | 180 }
  | { kind: 'edit'; invitation: Invitation }; // 수정 내용 저장까지 같이
interface PaymentService {
  products(): Promise<LetterProduct[]>;
```

## 6. 오류·경계
- 시각 경계: `now === expiresAt`이면 기한만료.
- 구매 중 버튼 연타: 처리 중에는 버튼 비활성.
- 화면을 열어 둔 사이 상태가 바뀜(예: 만료): 구매 시 서비스가 현재 상태로 다시 판단(활성화 중이 아니면 연장 거부 → "초대장 상태가 바뀌었어요. 다시 확인해 주세요.").
- 사용불가 초대장: 구매 거부(`blocked`), 수정·공유·방명록 버튼 없음, 삭제는 가능.
- 결제 시트 실패: "결제에 실패했어요. 잠시 후 다시 시도해 주세요." / 취소: 안내 없음.

## 7. 테스트
- 단위(jest): 화면 상태 계산(경계 시각·제재 우선), 기간 계산(첫 활성화·활성 중 연장·만료 후 재활성화), 구매 금액 합계, 레터 부족 시 아무것도 바뀌지 않음, 사용불가 거부, 기록 추가 형식, 충전, 연도 필터 선택지, "New" 판정, 예전 저장본 보정(`active` → `final`, `number` 생성), 이름 1~30자.
- 브라우저 점검: 목록·필터 → 활성화 구매(부족 → 충전 시트 → 돌아와 구매) → 공유 → 기간 연장 → 방명록 관리(신규·삭제·더보기) → 더보기(이름 수정·이력·삭제) → 활성화된 초대장 수정(레터 −5) → 지갑 내역.
- 완료 전 `npx tsc --noEmit`, `npx jest`, `npx expo lint`, `npx expo-doctor`.
