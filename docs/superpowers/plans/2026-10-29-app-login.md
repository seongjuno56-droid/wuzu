# 1-B 앱 로그인(카카오·구글) 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 앱의 가짜(mock) 로그인을 Supabase Auth 의 카카오·구글 로그인으로 바꾸고, 회원이 Supabase `profiles` 에 쌓이게 하며, 플레이스토어가 요구하는 계정 삭제(앱 안 탈퇴 + 탈퇴 요청 웹페이지)를 갖춘다.

**Architecture:** 앱은 Supabase OAuth 를 시스템 브라우저로 연다(PKCE, `expo-web-browser`). 그래서 카카오·구글 SDK 없이 Expo Go 에서도 확인할 수 있다. 회원 행은 `auth.users` 에 들어올 때 DB 트리거가 만든다. 앱은 `profiles` 를 자기 행만 읽고(RLS), 바꾸는 일은 모두 `security definer` RPC 로 한다. 탈퇴는 30일 유예 뒤 DB 함수가 개인정보를 지우고 `auth.users` 행을 지운다(결제·레터 기록 보관을 위해 `profiles` 행은 익명으로 남긴다). 탈퇴 요청 웹페이지와 처리 화면은 기존 어드민(Next.js, Vercel)에 붙인다.

**Tech Stack:** Expo SDK 57, expo-router, zustand, jest / `@supabase/supabase-js`, `expo-web-browser`, `react-native-url-polyfill` / Supabase Postgres(트리거·RLS·RPC·pg_cron) / 어드민 Next.js + vitest + PGlite

**Spec:** `docs/superpowers/specs/2026-10-27-server-and-admin-design.md` (3장 로그인 줄, 4장 데이터, 7장 앱 쪽, 8장 단계). 2026-10-29 사용자 결정으로 바뀐 점은 Task 1 에서 설계 문서에 반영한다.

## Global Constraints

- 로그인 수단은 **카카오 + 구글만**. 이메일 가입·로그인·아이디 찾기·비밀번호 찾기는 없앤다. 네이버는 안 한다. 애플 로그인은 iOS 출시 때(이번 범위 밖) — 사용자 2026-10-29 결정.
- 우선 대상은 플레이스토어(안드로이드). 한국 사용자가 1순위, 해외 사용자가 그다음.
- Supabase 지역은 서울(ap-northeast-2)로 확정. 다시 묻지 않는다.
- 2026-05-30 이후 만든 Supabase 프로젝트는 Data API 로 표·함수를 쓰려면 `grant` 가 명시적으로 있어야 한다. 새로 만드는 표·함수마다 필요한 `grant` 를 마이그레이션에 쓴다(`anon`/`public` 에는 아무것도 주지 않는 것이 기본).
- 가입 지급 50레터는 이번 범위가 아니다(설계 8장: 2단계에서 레터 원장 서버화와 함께).
- 주석·커밋 메시지·화면 문구는 한국어. 커밋 끝 줄 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- 앱 테스트 `npx jest`, 어드민 테스트 `cd admin && npx vitest run`. 앱 린트 기준값 21 errors / 7 warnings 보다 늘지 않는다.
- Prettier 를 프로젝트 설정 없이 파일 전체에 돌리지 않는다(서식이 통째로 바뀐다).
- Supabase 환경변수가 없으면 앱은 지금처럼 mock 서비스로 돈다(개발·테스트용).

## Review Focus

1. **로그인 창을 닫거나 취소함** → 오류 없이 로그인 화면에 그대로 남는다(`cancelled`). 테스트: Task 5.
2. **정지(banned) 회원이 로그인** → 세션을 바로 끊고 "제재된 계정" 모달. 다른 화면으로 넘어가지 않는다. 테스트: Task 5.
3. **탈퇴 신청 중 회원이 로그인하고 철회하지 않고 닫음** → 세션을 끊는다(로그인된 채로 남지 않는다). 테스트: Task 5.
4. **로그인한 회원이 남의 `profiles` 행을 읽거나, RPC 로 `status` 를 직접 바꾸려 함** → 막힌다. 테스트: Task 2.
5. **탈퇴 요청 폼에 스팸·빈값·아주 긴 값** → 저장 안 하고 안내 문구. 숨은 칸(honeypot)이 채워지면 저장하지 않고 성공처럼 보인다. 테스트: Task 3.
